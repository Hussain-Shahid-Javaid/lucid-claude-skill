# Lucid v0.2.0

This release adds two features:
- **originality checking**: check a new idea against existing work before calling it new
- **plain-language replies**: write answers the way a knowledgeable colleague would

## Originality checking

`lucid invent` takes an idea through these steps:
1. Define the problem.
2. Propose candidates that differ in how they work.
3. Check them against Lucid's own records, so the same idea isn't presented twice, even under a new name.
4. Search existing work.
5. Give each candidate a status that is limited to what was searched.

| Status | Meaning |
|---|---|
| known | already exists |
| adaptation | a known idea applied elsewhere or extended |
| potentially original within the documented search scope | nothing equivalent was found in what was searched |
| unresolved | the search couldn't settle it |
| not assessed | no allowed search ran |

What it will not do:
- Lucid cannot browse. Web searches are the host assistant's own, and they are logged with `invent search-log` and `invent add-source`.
- A failed search counts as a gap, not as proof that nothing exists.
- Without an allowed search, external originality stays "not assessed".
- Results are never phrased as "nobody has thought of this".

Other parts of the feature:
- Ideas that only rename, rephrase or add "AI" are flagged.
- So are combinations that give no reason why they are better.
- Whether an idea works is tested separately (`invent value`). A failed check marks it invalid however new it looks.
- `invent gate` keeps only qualifying ideas and says plainly when none qualify.
- Ideation, prior-art and skeptic workers can run in parallel on one shared budget. Each records its verdict without seeing the others. Agreement between them is not treated as evidence.

**Held-out result.** The probes were written by the same developer, so treat these as counts, not general rates.

| | Lucid | Keyword-overlap baseline |
|---|---|---|
| False originality claims | 0 of 13 | 4 of 13 |
| Known equivalents detected | 5 of 8 | 7 of 8 |

When a comparison is weak, Lucid says "unresolved" instead of guessing. That avoids false claims but leaves more for a person to check.

An earlier held-out set exposed two false claims. The fix is disclosed in the report, and that set no longer counts as held out. See `reports/evaluation-heldout.md`.

## Plain-language replies

The skill now tells the assistant to:
- put the answer first
- use familiar words
- answer simple questions briefly
- use structure only when it helps
- keep every fact, caveat and line of code exactly as it was

It also runs a five-question readability check before sending. This check needs no extra model call.

`lucid plain check` is an optional local helper. It flags:
- stiff or wordy phrases
- canned openers and closers
- jargon
- long sentences
- acronyms that aren't explained

`--fix` changes only safe word swaps. It reports any change to numbers, code or hedges; there should never be one.

Lucid's own error messages and dashboard text were rewritten to follow the same rules, and a test keeps them that way.

## Upgrade

Run `pip install -e .`, or reinstall the skill. Migration `0003` runs automatically on first use. Back up first with `lucid backup <file>` if you want a copy.

## Not in this release

- MCP tools for `invent` and `plain`. They are CLI only for now.
- Any measurement of how well a live model follows the writing rules.
