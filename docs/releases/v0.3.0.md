# Lucid v0.3.0

This release adds three features:
- **quality gates**: work isn't called done until it passes its checks
- **email, Slack and Teams messaging**: optional, and only within limits you set
- **an avatar representative**: optional, built from your own likeness and always disclosed

## Quality gates

`lucid quality` turns "professional quality" into checks you can see.

1. **Plan.** You write acceptance criteria first and mark each one required or optional. Then pick a profile that fits the risk: trivial, standard, release or production.
2. **Run checks.** Each result is tied to a hash of the exact files the check depends on. Edit those files and the result goes stale, so the check has to run again.
3. **Review.** A check that passed only after its tests or its definition changed is held until an independent review covers it. Reviews must list what they examined and name concrete problems; praise alone doesn't count.
4. **Gate.** The gate says `verified`, `failed` or `verification_pending`. With a pending result it lists the exact blockers, and it always reports:
   - the checks actually run
   - known defects by severity
   - checks not run
   - limits

The target is no known blocking defects within the verified scope. That is not the same as zero errors.

Lucid's own release now goes through this gate (`quality.json`). The gate report for this release (`quality-gate.md`) is attached to the release. Setting up the gate found real problems:
- Errors in the decision timer were swallowed silently.
- Avatar activation could stop halfway.
- A concurrent S3 create could return no manifest.
- Some exception handlers caught everything instead of the expected errors.
- About 50 type errors.

All of these are fixed.

**Independent review.** A separate reviewer tried to break the new modules and found 22 defects: 1 blocker, 14 major and 7 minor. Ten more passes over the fixes found 30 more, 10 of them major. Each one is fixed and has its own regression test. Some examples:
- A typed "passed" could replace a failed automated check.
- A caller could unlock private memory by declaring a narrow audience.
- Lucid's own message edits skipped the policy.
- The avatar answered a speaker who was missing from the participant list.

## Email, Slack and Teams (optional)

Connecting an account only lets Lucid draft. Sending needs a policy you set:

| Mode | What happens |
|---|---|
| Send after review | You approve the exact text. Any later edit needs approval again. |
| Automatic | Lucid sends within your recipients, channels, rate limits, working hours, allowed commitments and escalation words. |

Automatic messages say Lucid wrote them for you. Lucid never sends as anyone else. It won't claim you did something without evidence, and it won't make a promise, approval or purchase you didn't allow. Incoming messages are treated as data: instructions inside them can't add recipients or unlock memory.

**Delivery.** Sends are idempotent and claimed one at a time. Lucid honours Retry-After. If a send's outcome is unclear, Lucid looks for the message before it ever retries.

**Tested against:** fakes that follow the official Slack, Gmail and Microsoft Graph docs. It has not been tried with a live account yet. These are not supported:
- Slack drafts
- sending to Teams as a bot
- editing or deleting Teams messages

## Avatar representative (optional)

You build the avatar from your own photos and video. Your voice needs a separate consent. You review a preview before activating it, and you can revoke it or delete it. Deletion gives a report on each item.

**Meetings.** The avatar joins only meetings you approved, by meeting or category and by host. It is always shown as "Lucid — AI representative for you", and the disclosure is repeated for anyone who joins late. It answers only from knowledge approved for everyone present. Commitments and opinions are passed back to you. Even allowed commitments are accepted only provisionally, for you to confirm.

**Controls.** Interruptions and takeovers stop speech at once. Avatar, speech and meeting costs are metered separately from model tokens, and the avatar leaves when it reaches its cost or time limit. The meeting summary uses only what was said.

**Tested in:** simulation, and a local WebRTC demo in headless Chromium. No meeting platform or avatar vendor is integrated:
- Slack huddles have no API for apps.
- Teams meeting bots need a separate .NET media bot on Windows.

## Upgrade

Migrations `0004` to `0006` run on first use. Optional tools for the release gate are ruff, mypy and pip-audit; install them with `pip install -e ".[dev]"`.
